# 小小主角

## 当前完整浏览器试用版（2026-10-27）

默认书架已统一为用户指定的第一级15篇，使用 `current-edition.js` 的同一版本清单衔接阅读、识字统计、打印和后台订单。默认三人家庭为99页正文、117页合集；家庭人数改变时正文、目录及总页数自动重算。15篇合订1册，有一套封面、目录、连续页码和15页识字小结。下文6篇、20篇、30篇及每10篇分册的说明属于历史实现，不再作为当前浏览器打印清单。第二级等独立校样入口不等于默认打印服务开放。

双击“打开管理后台.cmd”，完整试用入口为 <http://127.0.0.1:4180/>，后台为 <http://127.0.0.1:4180/admin>（本机密码111）。可设置照片与姓名、阅读15篇、恢复进度、导出/恢复本机备份、提交打印需求，并在后台下载实际PDF。4173只提供静态阅读，不收打印订单。当前试用无需正式微信或商户账号，不产生扣款、不自动发货。

新版阅读记录按内容版本单独保存；已有小主角和照片沿用，旧版阅读记录保留但不套到新版故事。打印商品编号为 `level-1-fifteen-v1`，独立于旧6篇样册，初始价格为空。旧订单保持原快照，不能将旧版PDF标为新版15篇。详细范围、试用步骤及待用户决定事项见 [浏览器试用说明](docs/browser-trial.md)。

面向 3–6 岁儿童的中文分级阅读小程序。孩子使用真实照片头像和自己的名字作为绘本主角，人物采用绘本中的大头比例。故事预先制作，用户不需要生成故事。每份资料设置一位小主角；浏览器版可选择一起出场的家人，并为小主角及兄弟姐妹分别设置照片头像，爸爸、妈妈、爷爷、奶奶统一使用卡通人物。孩子资料不上传服务器；原生小程序启用微信登录后，云端仅保存家长账号标识和登录会话。

## 使用

本机已安装 Node.js，双击项目中的“打开本地预览.cmd”即可启动并打开浏览器。也可在项目目录运行 `npm run preview`，然后在浏览器打开 `http://127.0.0.1:4173`。进入“小主角”，选择照片、等待自动提取头部、填写名字并保存，再回书架阅读。浏览器预览把资料保存在当前浏览器；刷新页面后仍能恢复。清除浏览器站点数据会清除这份本地资料。

`127.0.0.1` 只能用于运行服务的电脑，手机上的这个地址指向手机自己。手机试用需要手机可访问的独立地址；仅把本机链接发送到手机不能连接。不同设备、浏览器或网站地址的资料各自保存，不自动同步。

测试纸质打印完整流程时，双击“打开管理后台.cmd”，用户端打开 `http://127.0.0.1:4180/`，管理员打开 `http://127.0.0.1:4180/admin`（本机测试密码111）。用户选择级别、确认打印并同意用途后，生成的个性化文件和分册清单保存在本机后台，管理员在“打印订单”下载。普通4173预览与公网静态试用站尚不接收打印需求。4180和4173是不同浏览器资料空间，可用“我的”中的备份恢复迁移当前人物及阅读进度。

手机浏览器试用地址：[小小主角](https://little-story-reader.zippyelm16.chatgpt.site)。试用站点仅所有者可访问，需要时登录创建站点所用的 ChatGPT 账号。照片与名字仍保存在当前浏览器，不上传到站点。它是浏览器试用版，独立于微信小程序发布。

微信开发者工具中导入本项目根目录，源码目录为 `miniprogram/`。当前 `project.config.json` 使用游客模式 `touristappid`，没有配置正式 AppID。开发者工具版本若不支持游客导入，可在新建项目时选择“测试号”，或在获得自己的 AppID 后替换该字段。正式手机预览及发布需要小程序账号、AppID 和开发者工具登录。

## 家长登录与绘本模块接口

原生微信书架底部新增“家长登录 / 我的账号”，包含登录、账号、用户服务说明和隐私说明页面。登录需由家长主动勾选同意，默认不勾选；不申请手机号、微信昵称或微信头像。首次成功登录自动建立家长账号。游客可直接阅读，登录没有新增内容或付费权限锁。

当前仓库仍使用游客 AppID，`miniprogram/config/auth.js` 的环境 ID 为空。未配置时仅可游客阅读，登录按钮明确提示尚未开通，不能将本机存储标记视为真实身份。浏览器预览可查看账号和登录页面，提示真实登录需在微信小程序完成，不生成模拟账号；浏览器资料仍沿用原本的本机保存方式。

### 开通真实微信登录

1. 在 `project.config.json` 中把 `touristappid` 换成自己的正式小程序 AppID，在微信开发者工具中登录该项目。
2. 开通微信云开发环境，并关联同一个小程序 AppID；将环境 ID 填入 `miniprogram/config/auth.js` 的 `envId`。此文件不需要 AppSecret，也不要把任何私钥放入前端。
3. 在该环境创建 `story_users`、`story_sessions` 两个数据库集合。**两个集合分别设置为仅管理员可读写**，或在各自权限管理中应用 `cloudfunctions/account/database.rules.json` 的规则；该文件是规则模板，上传云函数不会自动应用数据库权限。
4. 对 `cloudfunctions/account` 执行开发者工具“上传并部署：云端安装依赖”，使用支持 Node.js 18 或更新版本的运行环境。其依赖固定为 `wx-server-sdk@3.0.1`；客户端使用微信基础库内置的 `wx.cloud`，无需安装浏览器登录 SDK。
5. 微信中验证：首次同意并登录 → 返回书架 → 设置小主角 → 退出并重新进入 → 恢复登录 → 退出账号 → 再次登录。分别测试断网、会话过期和不同微信账号。上述真实环境与设备验证不能由本机测试替代。

接口依据：[微信云函数与可信调用身份](https://docs.cloudbase.net/recipes/add-cloud-function-wechat-miniprogram)、[数据库仅管理员读写规则](https://docs.cloudbase.net/rule/rule-example)。

### 数据与模块边界

- `miniprogram/services/auth-service.js` 负责登录、恢复、退出和会话失效。身份来自云函数内的 `cloud.getWXContext()`，不采信客户端传来的 OpenID 或用户 ID。用户 ID 为 AppID 与 OpenID 派生的稳定标识；原始 OpenID 不返回页面。会话为随机凭证，云端仅存 SHA-256 摘要，绑定微信身份并在7天后过期；多设备会话相互独立。
- `cloudfunctions/account` 提供 `login({consentVersion})`、`session({token})`、`logout({token})` 三个操作，返回 `{ok,user,expiresAt}`，仅 `login` 额外返回 `token`。账号数据为创建时间；会话数据包含用户 ID、创建与过期时间及同意版本、同意时间。过期检查在服务端执行，过期记录不会自动删除；可由管理端按 `expiresAt` 清理。数据库失败不会回退为登录成功。
- 页面只通过 `getSnapshot()` 取得不含凭证的身份视图。重启后必须向云端验证本机记录；网络失败保留记录以便重试，界面不显示已登录。退出优先清除本机会话，再尝试云端撤销；断网时说明远端撤销未完成。旧登录响应和旧绘本请求不能覆盖退出后的状态。
- `getApp().getReadingContext()` 返回 `{userId,child,storage:'local'}`，供阅读及未来绘本模块共用。`getApp().auth.callWithSession(functionName,data)` 为后续云函数附加 `sessionToken`。服务端的 `createAccountService(repository).requireUser(cloud.getWXContext(),event.sessionToken)` 校验身份并返回可信 `user.id`，业务记录必须归属于该 ID，不相信前端传入的归属。`service.js` 与 `repository.js` 是可复用的服务代码；新云函数独立部署时需将其打包到自身目录或共享依赖包，不能直接依赖未随函数上传的兄弟目录。
- 微信的书架、角色设置和阅读页共用 `getApp().getProfileStore()`。游客继续使用旧资料键，家长账号使用独立本机资料键；登录不自动转移游客资料，不上传孩子照片。账号页“导入本机游客资料”明确说明将替换当前小主角，经家长选择后复制姓名、年龄、班级及头像；复制后的照片独立保存，后续删除不影响游客原头像。保存期间切换账号会中止提交并清理新照片。

`npm run test:auth` 验证服务端身份校验、会话恢复/撤销/过期、请求竞态、错误重试和本机资料隔离；`npm run test:auth-browser` 验证浏览器页面、说明链接、勾选状态、游客阅读和多尺寸布局。浏览器测试不代表真实微信登录已部署。现有 `npm test` 包含账号单元测试，`npm run check` 校验原生页面和语法。

## 产品行为

- 书架和主角设置使用竖屏；阅读页允许跟随手机旋转。竖屏进入阅读时提示横过来，转横后显示左右图文。
- 浏览器版十本书均有正式封面，书架与阅读入口显示对应书名和插画。首次开始或读完后重读时先显示封面，点击“翻开故事”进入正文第一页；封面不计入正文页数。在正文第一页点击“封面”可返回封面。已有第二页及之后的阅读进度时，“继续阅读”直接恢复正文位置，不要求再次翻过封面。微信原生页面暂不提供上述封面流程。
- 浏览器前六本为《你好，我是小石头》《我的花》《我家有几口人？》《我的小手》《下雨了》《小石头回家》。名字、年龄、班级替换故事中对应位置；家庭书的文字、页数、人数与插画随所选家人同步变化。微信原生仍支持前三本的兼容插画。
- 浏览器版《你好，我是小石头》六页使用暖色水粉与纸张拼贴画风，通过打招呼（`greeting`）、玩耍（`play`）和上学（`school`）三种场景表现自我介绍。姓名、年龄和班级仍只替换预编故事中的对应文字，正文独立于插画。此书只使用小主角的照片，保留原脸部、发型和表情，不调用家人照片，也不生成新的脸部姿态。
- 浏览器版《我的花》六页保留暖色水粉与纸张拼贴画风，人物统一黄色上衣、绿色短裤。护花、追花瓣、寻找使用已登记的同母版透明动作，所有动作复用同一头像，不生成新的表情或五官。正文使用独立文字层，风中花瓣按故事进度独立绘制。
- 浏览器版《我家有几口人？》使用同类纸张拼贴画风的庭院、独立身体与头像图层。爸爸、妈妈、爷爷、奶奶使用固定卡通头像与成人身体，具有更长的躯干和腿部、更宽的肩部；小主角及兄弟姐妹使用独立儿童比例，可换真人照片。儿童真人头像按脸部边界匹配身体，不按头发长短缩小脸部。人物数量、站位和场景根据出场名单排布，完整头发保留在各自人物区域内。微信原生版的三本书仍使用原有插画。
- 浏览器版选择 JPG、PNG、WebP，或当前浏览器能原生解码的 HEIC/HEIF 照片，单张最大 20 MB。按文件头识别内容，兼容相册返回空白或错误的格式标签。通过本地 Blob URL 读取，30 秒内未完成文件读取或解码时给出重试提示；不支持 HEIC 解码的浏览器提示改用 JPG/PNG。原照片在识别模块取得缩小副本后释放，不保留整份 Base64 副本。
- 首次使用下载本站托管的识别模型，照片仅在当前浏览器内处理。自动定位人脸、摆正眼睛方向，保留真实头发和脸部，排除背景、脖子与衣服，再用透明头部拼接固定卡通身体。用户提供孩子高清、正面、头顶完整的上半身照片即可，上传后自动适配大小、位置和场景角度，不显示手动调节。导入和识别失败的具体原因显示在选图区域并滚入可见位置，不能只在页面底部显示通用失败提示。
- 浏览器头像提取只生成一次完整透明图片，再由 `character-rig.js` 按固定 `child-v1` 母版归一化，以下巴连接动作库中的领口。每个动作先缓存完整透明人物；场景仅整体定位、旋转和等比缩放，不再逐页拼头。完整头发轮廓用于扩展镜头，不因长发而缩小脸部。读取旧资料时忽略儿童头像的历史手动偏移，保存时保留原 PNG、关键点、姓名及其他家庭资料。成人旧照片资料保持原样且不参与渲染。
- 新提取的真人头像按人脸边界匹配人物头部大小，头发长度和透明留白不参与脸部尺寸计算，保持照片比例不拉伸。完整头发与脸部一起绘制；《我的花》在头部超出画面时让镜头整体退远。旧版已提取的头像仍按可见边界定位，重新选原图才能取得人脸边界或恢复先前已被裁掉的头发；仅手动裁剪的旧头像也需重新提取。
- 十本浏览器阅读及 PDF 共用 `preview/family-character-loader.js` 的人物会话。`character-session.js` 初始只准备第1–3本所需动作，开始第2本后移至第2–4本，依此类推；共享动作去重，窗口外解除合成人物引用。封面复用站立人物，不因同时显示十张封面加载所有后续绘本的动作。换头像取消旧会话，保存不等待整册页面绘制。旧版 `intro-art.js`、`flower-art.js`、`sequence-art.js` 仅保留给原生兼容和旧审阅页，正式浏览器入口不再调用它们。
- `layered-art.js` 保存五本迁移书的原情节顺序、背景、动作、道具及取景；家庭书仍按实际名单排布。新增背景仅通过内置 imagegen 清除原场景中的主角身体，雨伞单独提取，未重生成真人或儿童身体。素材来源及完整提示词见 `content/layered-art-provenance.json`、`content/layered-art-prompts.json`。交付素材使用逐像素核对的无损编码；原生像素仍为1672×941，不因人物缓存或PDF输出300dpi而视为整册300ppi。
- 浏览器版家庭书默认小主角、爸爸、妈妈三人，允许一至十二人出场，小主角始终保留。爸爸、妈妈、爷爷、奶奶、哥哥、弟弟、姐姐、妹妹均可勾选；同种兄弟姐妹可以继续添加，例如分别设置两位姐姐的头像。只有小主角及兄弟姐妹可独立选图或恢复默认绘本形象，四种成人角色不提供照片导入或头像位置调整。未勾选的基础角色仍保留本地资料，移除额外成员后须保存才提交删除。编辑器为同种角色编号，故事中仍使用“姐姐”等自然称呼。
- 家庭书逐个介绍已选家人，再讲“数家人时忘了自己，最后把自己算上”的小故事。人数包括小主角，不默认存在父母或祖辈，不让未选家人出场或说话。仅选小主角时使用四页短故事，避免写出“零口人”；多人故事的页数随介绍的人数增长，最多十六页。
- 提取时为头顶预留空间；与脸部连接的头发触及取样区域任一边时扩大该侧范围，最多重试两次。脸部皮肤在下巴附近结束，头发可延伸到下巴以下，不再按下巴裁掉长发。原照片本身截掉头发、或扩大后仍无法提取完整时提示换图，不生成虚构头发。分割输入最长边限制为 512 像素，输出纹理单独保留较高分辨率。细发边缘可能保留少量背景混色；独立发辫、发饰和极宽发型的效果取决于分割质量，不能保证所有照片完全一致。
- 照片里有多张可识别的人脸时必须点选当前角色；无脸、脸太小、模型加载失败或分割不清时显示错误，不能将整张照片作为新头像保存。用户可换图、撤销本次选图或取消修改。切换角色会取消尚未完成的照片任务，不会把前一个角色的处理结果填给后一个角色。原照片不持久保存，重新提取需再次选择原图。
- 浏览器用同一条 version 4 记录原子保存 `profile`、`members` 与 `avatars`。成员保存稳定的 `id`、角色 `role` 和出场标记 `included`；头像映射按成员 ID 保存透明图片、绘制布局及头部边界/下巴信息，新提取头像另存 `faceBounds` 人脸边界。额外兄弟姐妹使用独立 `member-*` ID，移除其中一人不会改变其他人的头像对应关系。
- 旧版已保存的成人照片数据仍保留在当前浏览器中，更新或保存家庭名单不会擅自删除；读取时不解码这些照片，缩略图、人物预览、书架和故事均不再显示成人真人照片。成人角色始终使用卡通形象，即使渲染输入还包含旧头像也忽略。儿童与兄弟姐妹的照片继续正常读取和使用。
- 读取 version 1/2/3 资料时保留旧家庭书的五人名单，并加入已保存头像的兄弟姐妹；version 1/2 的主角头像也可恢复。迁移后的资料在点击保存时统一写入 version 4，不能因新用户默认三人而自动丢掉旧家人。单个家人头像损坏不会影响其余资料。取消设置撤销所有未保存的成员、照片及资料修改，撤销选图只恢复当前角色。
- 微信原生页面仍使用手动裁剪和原有固定五人、八页家庭故事，尚未接入浏览器的动态成员及新家庭插画。浏览器自动识别模块依赖 WebAssembly，需要另行适配微信运行环境，不能直接认为原生版本已具备同样功能。
- 名字去除首尾空白后为 1–8 个 Unicode 码点，禁止换行和控制字符。年龄为 3–6 岁，班级为小班、中班、大班。
- 编辑过程属于草稿；只有点击保存才提交。取消裁剪、返回书架、离开页面不覆盖原资料。
- 微信版本将裁剪结果复制到小程序私有持久目录，资料写入成功后才清理旧头像；失败保留旧资料。丢失头像文件时保留姓名并显示示意头像。
- 微信本地资料和浏览器预览资料互相独立，不进行云同步。删除小程序数据或浏览器站点数据后，需要重新设置。
- 第一级规划为累计 200 字、30–40 本书。本地版先跑通三本；故事优先自然有趣，不为字表强行罗列数字或插入词句。

## 结构

人物制作采用“统一角色标准 → 独立动作素材库 → 预合成完整人物 → 场景整体摆放”的顺序。`miniprogram/lib/character-rig.js` 是独立人物管线：`child-v1` 在逻辑坐标中固定头部参考高度300、站立领口至地面640（约3.13头身），以领口为原点；不是要求所有页面显示相同像素大小。真人头像按关键点只归一化一次，保持真实五官、脸型、发型和透明轮廓；头发长度不参与脸部大小计算。动作只允许变更姿态、领口角度，不得改变头、躯干和四肢的固有比例。蹲姿的外接框高度可以变小，不能将蹲姿重新拉伸为站立高度。

`content/child-pose-library.json` 注册独立身体素材和领口位置。所有动作素材共用母版的像素密度（1176源像素对应640身体逻辑单位），动作配置也不能覆盖此换算；画布边界可以因姿态变宽、变矮，但人物不能单独重采样成另一种大小。身体素材必须独立于背景。新动作在制作时沿用同一人物母版，四肢尺寸须以母版核对，不能重新生成一个比例不同的人物再调整头部掩盖。编程接口不能从未经核对的位图自动证明四肢符合母版，动作素材仍须视觉验收。合成模块按头像、动作版本、身体缓存完整透明人物；各本书只能调用已注册动作，场景摆放接口仅接受位置、整体旋转和一个等比缩放值，拒绝单独头部参数、横纵不同的缩放。色调适配可以改变渲染副本的颜色，不能改变这些几何关系。

浏览器 `?view=character-standard` 是独立模板的比例验证入口，优先读取本浏览器已保存的真人头像，以不同整体大小展示同一个已合成人物。兼容边界：介绍、花及后续三本的旧身体与背景仍合画，其旧合成器保留以维持现有阅读；这些素材不能视为已迁入独立人物库。只有背景、人物和需前后遮挡的道具分层，并注册合格动作后，书页才能切换到新管线。新管线不接受旧书中的逐页 `photoPose.face/headFrame` 作为比例来源。

新版30篇稿的插画审阅入口为 `?view=first-five`（第1—5篇）、`?view=next-five`（第6—10篇）和 `?view=books-11-15`（第11—15篇）。它们复用固定A5封面、图文页和识字小结，读取本机资料但不写入阅读进度；识字累计按完整故事顺序统计。第11—15篇场景在 `preview/books-11-15-scene.js`，推车、托物、蹲姿伸掌动作及手掌接触点在统一人物库注册，场景只移动和等比缩放完整人物。原生素材、透明边界和生成提示存于 `art-samples/books-11-15-native/generation-complete.json`；`tests/books-11-15.browser.cjs` 验证翻页、保存资料、家庭角色、三本准备窗口和关键情节几何，并导出本机审阅截图。这些入口是内容校样，不自动替换正式书架或印厂文件。

`?view=books-16-20` 审阅第16—20篇，场景定义在 `preview/books-16-20-scene.js`，新增坐姿看书、坐姿绘画、赤脚站立、喝水和浇水动作，均沿用统一人物库的像素密度。叶柄、壶柄、杯底和笔杆按素材接触点与人物手掌连接；纸张的贴地透视只作用于道具平面，人物始终整体等比摆放。原生PNG、提示词及未采用版本的标记存于 `art-samples/books-16-20-native/generation-complete.json`。`tests/books-16-20.browser.cjs` 核对38页正文、5套封面和小结、真实头像格式的测试样本、单亲家庭替换、识字累计和本机资料保留；测试头像为示例素材，不代表已完成真实手机照片验收。`scripts/package-books-16-20.py` 将默认卡通校样和原生素材打包到本机输出目录，不包含用户照片。

`miniprogram/lib/character-session.js` 管理新人物管线的分批准备。上传并保存头像后仅后台准备前3本需要的动作；开始读第2本时再准备第4本，窗口始终为当前本及后2本，共享动作去重。任务串行、可暂停，当前阅读可抢先于未完成的后台加载；窗口外人物解除合成缓存，换头像应关闭旧会话。不要预生成所有正文PNG，页面按需绘制、打印时才逐册导出。此策略控制计算和缓存，不增加绘本访问权限锁。验证样稿使用该会话模块；旧合画绘本保留既有逐页加载与下一页预取，尚不能算已经接入新动作库的分批合成。

`scripts/benchmark-composition.cjs` 使用已提取的示例头像测量现有6本或前3本的素材加载、1400×788页面合成、PNG编码和像素缓冲估算，分别运行本机CPU及4倍降速模拟，每种条件3次。结果写入本机 `.local/composition-benchmark.json`，不发布头像或测试产物。新动作库仅报告实际注册的动作数和缓存命中时间；不包含头像识别及真实手机网络，像素缓冲值不等同于浏览器实际峰值内存。

`miniprogram/pages/` 是原生微信页面；`components/story-art/` 是 Canvas 2D 绘图组件；`lib/` 共享人物绘图、故事、资料校验和裁剪算法；`services/profile-store.js` 负责微信本地持久化。`preview/` 是独立浏览器开发预览，`scripts/` 负责构建、静态预览及项目检查，`tests/` 包含行为验证。

`content/level1-character-plan.json` 保存从既有讨论恢复的200字初稿与前三组；第四组以后的教学顺序尚未定稿。`content/level1-stories-04-10.json` 保存第4至10本正文。第4至20本通过 `scripts/build-approved-stories.cjs` 生成 `miniprogram/lib/level1-approved.js`，浏览器调用故事目录时显式传入 `{includeApproved:true}`，上架二十本；原生微信目录仍保留已支持的三本。第7至10本《山不见了》《小车回家》《小球在哪》《水中的我》已完成独立背景、透明道具及完整人物分层插画，接入阅读与合集导出。新图原稿在 `art-samples/first-ten-native/`，原生像素无损交付在 `preview/art/sequence/first-ten/`；完整提示词和来源在 `content/first-ten-art-provenance.json`，逐页情节与合成方案在 `miniprogram/lib/first-ten-art.js`。山景按原故事要求固定观察位置，云遮挡与揭晓不改变山的位置；车库镂空与门片独立于玩具车；找球先在院内观察石头，第7页才显示室内的球；水面倒影镜像复用同一个已合成人物，触水散开、静止后恢复。运行 `npm run build:drafts` 核对书名、正文和重点字，生成手机文字对照页。第一级规划30个故事，现有20本不代表完整第一级。

`miniprogram/lib/literacy.js` 统一计算每册正文的不同汉字、本册首次出现字，以及按书架顺序累计的不同汉字。书名、标点、数字与个性化姓名插入位不计入；姓名在第一册小结单列，年龄、班级及动态家庭使用实际正文。累计是接触量，不代表掌握量，重读不增加；所有辅助汉字也计入。浏览器的介绍页、读完页和文字对照页共用该口径，不能把重点字数量或个人姓名当作累计识字量。

浏览器正文保持横向A4跨页比例，最后显示同纸色的识字小结。纸质版按竖版A5图文同页重排；整级合为一册，每个故事后有识字小结，整册共用一套封面。阅读与打印复用实际正文的识字统计、真人头像和场景色调适配。小结包含本书用字、新字、累计接触量和本书字表，累计量不代表掌握量。

`preview/photo-tone.js` 从脸部内侧取亮度分位数（排除发际和透明边），结合场景亮度为偏暗面部使用摄影曝光曲线，不以固定小幅增益代替曝光校正。曲线gamma限制为0.55–1.03，单像素曝光增益最多2.4倍；深黑发丝与高光有保护，正常曝光头像只作很小的亮度修正。冷暖按照片与场景差异调整，红蓝通道白平衡增益不超过3.5%。真人代入是产品核心：不得卡通化、重绘五官、磨皮或叠加插画纹理。只改渲染副本的RGB，不写回保存的头像，不改变alpha、坐标、五官、表情或完整发型。按原头像和参数缓存，翻页时复用结果；默认卡通头不调色。设置页头像预览也进行曝光校正，绘本阅读与打印共用场景适配入口。

`miniprogram/lib/portrait-fit.js` 统一约束真人头像与身体的比例。固定身体需预先校准真人头部框、领口和角度，不能从不同表情的默认卡通头像推断身体比例。各场景 `photoPose.headFrame` 使用背景源坐标中的 `crownHeight`；家庭身体的 `photoHeadFrame` 使用身体图块源坐标，由渲染器随身体共同缩放。真人关键点的脸部高度换算成头部参考高度（默认1.7倍），与该身体专属参考框、脸部宽高共同确定等比尺寸。缺少独立标定的旧素材才从原配卡通头高的92%推算兼容框。以下巴连接领口，不改五官、不裁头发；长发和蓬松头发仅扩展镜头，不参与脸部缩放。标定由作者完成，用户上传后自动适配，阅读与打印走同一合成入口。增加或替换身体素材时，须用同一真人头像跨书、跨姿势检查比例，不能只检查是否裁头发。

`miniprogram/lib/sequence-art.js` 与 `preview/sequence-art-loader.js` 组合第4至6本的独立场景、默认卡通头和本地照片头。`preview/art/sequence/<book>/manifest.json` 定义逐页镜头、领口和角度；物件特写可以不出现人物。全部图层完成后才显示，下一页可预取；新书加载失败显示文字和重试，不套用其他书的旧插画。

`sites/mobile-preview/` 是手机试用站点的独立源码仓库，`.openai/hosting.json` 保存既有站点身份与静态托管配置。运行 `npm run build:site` 同步已构建页面、`preview/vendor/`、`preview/models/` 中的本地识别资源，以及 `preview/art/intro/`、`preview/art/flower/` 和 `preview/art/family/` 插画资源；页面仅将“本地开发版”标题改为“手机试用版”。不发布测试照片和 QA 截图。后续发布应沿用同一站点身份和所有者访问权限。

`miniprogram/lib/intro-art.js` 组合自我介绍书的三种场景及独立头部，六页共用预制素材；`preview/art/intro/manifest.json` 保存场景文件与人物定位信息，`preview/intro-art-loader.js` 管理浏览器素材加载和缓存。头像来源仅为 `child`，运行时依照当前小主角资料缩放和定位，不生成新图片。

`miniprogram/lib/flower-art.js` 是浏览器使用的分层 Canvas 绘图模块；`preview/art/flower/manifest.json` 定义领口、人脸大小、花瓣与特写坐标，场景的 `photoPose` 专供已按眼线转正的真人照片使用，示例头保持原样稿定位。`preview/art-loader.js` 按当前场景加载 WebP 并复用缓存，每次打开页面重新验证小型位置配置文件。三本书在素材加载时只显示静态纸色等待提示，素材齐备后一次绘制，不先闪现旧版插画或无头人物；阅读时提前准备下一正文页，已缓存的页面直接绘制。加载失败时保留完整旧插画并允许主动重试。原始素材与生成提示保存在 `art-samples/my-flower-production/`，运行时不调用图片生成服务。

`miniprogram/lib/family.js` 负责家庭成员规范化、旧资料迁移、兄弟姐妹 ID、人数限制及动态家庭故事，输出逐页 `pages` 与 `scenes`。`canUsePhoto(role)` 仅允许小主角和四种兄弟姐妹角色使用照片，未知角色也返回不允许；界面、读取流程与渲染器使用同一限制。`stories.js` 在明确传入成员数组时使用动态故事；不传成员的原生调用保持旧书。浏览器构建器支持这些共享模块之间的本地 CommonJS 依赖。

`miniprogram/lib/family-art.js` 根据每页场景的 `memberIds`、`focusId` 与人数布置人物，按允许使用照片的成员 ID 获取真人头像、按角色获取身体及默认卡通头像；成人始终跳过旧照片与旧位置数据。多人场景使用共同缩放比例和各自占位，保留成人与儿童的身高关系。`preview/art/family/manifest.json` 定义素材文件、身体与头部图块范围、领口/脚底位置和目标脸部尺寸。`preview/family-art-loader.js` 从同目录读取配置与 WebP 素材，完成加载后统一合成，失败可重试并回退到包含相同成员的原绘图。家庭人物在翻页时通过 Canvas 组合，运行时不请求图片生成服务。

`preview/face-processor.js` 使用固定版本的 MediaPipe Tasks Vision、人脸关键点和 Selfie Multiclass 模型，接口依据 [Google Face Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker/web_js) 和 [Image Segmenter](https://developers.google.com/edge/mediapipe/solutions/vision/image_segmenter)。人脸类别与头发类别构成分割遮罩，并以关键点限制脸部、下巴及邻近人物；同一人脸的自动适配复用分割结果。依赖来源与校验值在 `preview/models/assets.json`，运行库许可证在 `preview/vendor/mediapipe/LICENSE.txt`。

进入主角设置即开始准备识别工具；两个模型与运行库并行下载，模型实例仍按顺序创建，避免运行库初始化冲突。准备过程不需要照片，失败后选图可重试；同一页面内重复选图复用已加载工具。首次使用的网络下载仍取决于手机网速，不保证固定处理时长。

支持 CacheStorage 的浏览器另行缓存两个固定版本的识别模型（约 20 MB），再次打开页面可复用。此缓存只包含本站的公开模型二进制，不包含用户照片；按版本命名并校验文件长度。缓存不可用、读取失败或空间不足时回退网络读取，不阻止选图。保留 CPU 推理与 512 像素分割输入，避免 GPU 首次编译等待和缩小掩膜造成头发轮廓损失。

无需安装业务依赖。运行 `npm test` 检查资料保存、失败回滚、裁剪和绘图逻辑；运行 `npm run check` 检查原生项目配置及语法。浏览器交互测试使用 Playwright 和 Chrome，需在测试环境安装或提供 `NODE_PATH`。这些检查不替代微信开发者工具编译和 iOS/Android 真机测试。

`npm run test:face` 使用真实模型验证半身照、无脸照片、多人照片、透明头像、本地请求与保存恢复。默认测试照片放在 Git 忽略的 `.local/face-fixtures/portrait.jpg`，来源是 [MediaPipe 官方测试照片](https://storage.googleapis.com/mediapipe-assets/portrait.jpg)，仅本地验收使用，不发布到站点；也可通过 `FACE_TEST_PORTRAIT` 指定相同内容的本地文件。

`npm run test:flower` 验证六页插画、手机竖版图文、按需加载、失败重试及快速翻页。`npm run test:long-hair` 用 `.local/face-fixtures/fictional-long-hair.png` 中完全虚构的长发测试照片运行真实模型，检查发梢保留、衣服排除、人脸边界保存恢复与三种姿势的实际组合。测试素材和结果仅保存在本地，不发布到站点；性能测量不能替代手机实测。

## PDF下载和印厂校样

纸质版为竖版A5（148×210mm），每页上图下短句；完整每级计划30个故事，每10个故事合订一册，共3册，各故事是章节。当前前20个故事已完成插画，第1—10个作为第1册，第11—20个作为第2册样册，不把未来30个故事当作已完成内容。每册一套封面与目录，不为故事重复增加封面或空白扉页；每个故事后保留用字、新字、累计接触和字表。线上逐故事阅读及头像按需准备机制不变。

用户在书架进入“小主角的纸质绘本打印服务”，选择第1–10级，查看实际分册和目录后确认打印；第2–10级尚未开放。连接运营后台时，确认后填写份数、配送与文件保存同意，实际PDF及订单收到后才提示成功。纯静态手机试用站尚未连接收件后台，显示服务未开放，不模拟提交。制作人员可用显式 `?printTools=1` 打开原有PDF、印厂包与浏览器校样工具，普通用户界面不展示这些选项。
