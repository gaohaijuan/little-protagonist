# 商品报价、支付关联与用户详情

## 范围与金额规则

后台提供“商品价格”“支付订单”“资金流水”三个入口；打印订单详情中生成报价。现有已插画绘本初始化为无价格草稿，运营方填写每册价格并启用后才能报价，不预设真实售价。第1级合集以`level-1`单独登记无价格草稿；合集每册单价独立填写，不能自动累加6本单书价格，份数按整册计算。商品名称与版本、整数分单价及册数保存在报价快照中，后续修改商品不改变旧报价。应付金额为商品合计加运费减优惠，必须大于零；自取运费必须为零。报价有效期默认24小时，可设1–168小时。PDF已清理或订单已进入制作时不能报价。

报价后进入待付款。修改联系人、配送或册数使原报价失效，未付款的准备单关闭；保存相同资料或内部备注不使报价失效。已付款订单不能直接改资料和册数，保留异常与退款处理。已报价订单只有收到准确匹配的服务端付款核验才能推进制作，待处理退款、部分/全额退款或异常收款均阻止继续制作交付。无报价的旧人工订单继续原处理方式，人工状态不产生收入。

## 支付与退款的实际边界

`preparePaymentIntent` 仅生成带商户订单号的本地付款准备单，锁定报价、本人身份、币种CNY和微信/抖音渠道。准备单最长15分钟且不能超过报价期限；同一有效报价、同一渠道复用准备单。所有重试编号均绑定原内容，不能重用编号改订单。返回 `gatewayReady:false`，没有调起支付参数，浏览器不提供可扣款的按钮。平台用户只能准备本平台渠道，浏览器测试身份可以指定任一渠道。

尚未接入微信支付/抖音支付的商户下单、官方通知验签、主动查单、渠道退款、结算和手续费。商户配置就绪后必须实现对应服务，确认真实付款后才推送归一化事件；不能将小程序回调或前端自报成功当作已付款。签名事件接口是内部可信服务入口，不是支付渠道通知地址。

后台“登记退款申请”只登记金额、原因和请求编号，不执行渠道退款。待处理申请预占可退余额，金额不能超过实付减已退和待处理金额；重复请求不重复申请。撤销记录原因并释放预占，不会把真实渠道退款取消。即使申请已撤销，渠道最终确认的同一笔退款仍可按实际结果记账。部分退款累计不能超过原实付，同一退款流水不能换事件编号再次记账。

有效付款使打印订单进入待制作；订单取消、报价过期、准备单关闭或文件已清理后收到的真实付款仍记入资金流水，同时标为异常收款，不能自动恢复或制作。运营方应核对并通过真实商户服务退款。后台状态不会替代真实资金处理。

## API

所有后台接口要求管理员会话；写请求另外要求 `X-Admin-CSRF`。公开用户接口要求本人Bearer token或浏览器HttpOnly会话。

| 接口 | 请求 / 返回 |
| --- | --- |
| `GET /api/admin/products` | 商品列表，未填写单价为null |
| `PATCH /api/admin/products/:id` | `{version,name,unitFen,status:"draft"或"active"}`，启用要求正整数分价格 |
| `POST /api/admin/print-orders/:id/quote` | `{version,shippingFen,discountFen,note,validHours}`，note为用户可见的报价说明 |
| `POST /api/print-orders/:id/payment-intents` | `{quoteId,channel:"wechat"或"douyin",requestKey}`，返回本人准备单，不能扣款 |
| `GET /api/payment-intents/:id` | 仅本人付款单与核验流水，不含内部退款申请原因 |
| `GET /api/admin/billing?days=30&q=&page=1` | 按创建时间及打印订单号、付款单号、用户编号查询，每页25条 |
| `GET /api/admin/billing/:id` | 付款单、报价、资金流水、退款申请详情 |
| `POST /api/admin/billing/:id/refund-requests` | `{version,amountFen,reason,requestKey}`，仅登记申请 |
| `POST /api/admin/refund-requests/:id/cancel` | `{reason}`，撤销未结束的申请 |
| `GET /api/admin/users/:id?section=activity&page=1` | 全时间用户统计，分区支持activity、orders、payments、referrals |

请求编号为16–100位字母、数字、短横线。涉及金额必须为整数分；不可传浮点元数。商品、订单和退款申请登记使用版本防止旧页面覆盖新数据。写接口拒绝null、数组和无效JSON。

微信和抖音原生SDK提供 `sdk.preparePaymentIntent(orderId,{quoteId,channel,requestKey})`、`sdk.getPaymentIntent(id)`；账号切换时丢弃旧响应。页面需要展示报价、明确的家长购买确认后才调用准备接口。此SDK尚未包含调起支付能力。

关联付款单的内部核验事件必须包含以下字段：

```json
{"eventId":"unique_event","orderId":"PAY生成的商户订单号","transactionId":"渠道付款或退款流水号","userId":"付款单所属后台用户编号","kind":"paid","amountFen":3000,"currency":"CNY","channel":"wechat"}
```

退款使用 `kind:"refund"`、新的事件与退款流水号，可带后台 `refundRequestId`，有申请时必须匹配付款单和金额。签名算法、时间戳和独立服务端密钥沿用[付款核验说明](README.md)。不关联新准备单的既有商户事件保留兼容记账方式；它们只属于资金流水，不自动与打印订单匹配。

## 用户详情与保存

用户列表、邀请人/受邀人、订单和支付详情可进入用户详情，查看来源、加入/最近活跃、阅读绘本分布、打印订单、实付/退款、邀请人数及其中曾付款人数。详情统计为全部时间，不随列表日期改变；各分区25条分页。开始阅读次数不等同于读完或完成学习。只读运营数据，不暴露平台身份、会话哈希或token，不读取孩子照片和本地档案。此模块没有编辑会员权益、封禁或跨平台合并能力。

数据保存在现有私有SQLite目录，采用追加表方式兼容旧库。订单联系信息到期时同时清除报价说明、退款原因和撤销原因；支付金额、商户编号、流水、价格快照及审计动作保留用于对账。报价和准备单到期关闭；晚到核验仍按实际资金记账。清理随服务器启动及每分钟执行，停机后重启补清理，备份须同步执行个人信息期限。

## 验证

`node --test tests/billing.test.cjs tests/admin.test.cjs tests/print-orders.test.cjs tests/platform-sdk.test.cjs tests/operations-service.test.cjs` 检查草稿价格、快照、订单关联、幂等、金额及身份核对、签名、异常收款、退款预占/核验、访问控制和旧接口兼容。`node tests/billing.browser.cjs` 验证商品表单、报价、支付详情、退款登记/撤销、用户分区和桌面/手机布局。`node tests/print-orders.browser.cjs` 使用实际导出PDF回归打印交付；浏览器测试数据均在独立私有测试目录，模拟的支付事件不写入日常后台数据库。这些验证不代表微信/抖音真机收款或退款已开通。
