# 后台运行检查、操作记录与私有备份

## 运行与备份

管理员页面显示当前服务启动时间、运行时长、有效PDF数量与占用、配置的文件额度、所在磁盘剩余空间、SQLite主库及写入日志大小、最近清理检查时间。有效文件的磁盘存在检查最多5000份，并明确显示检查数量与是否达到上限。

提醒包括文件空间使用达到80%、有效期内PDF在磁盘缺失、待确认/待付款/待制作订单超过48小时、异常收款仍有余额，以及最近24小时服务错误。检查未发现问题只表示上述检查通过，不代表外部登录、真实收款或物流已经验证。微信/抖音和内部付款核验接口只显示服务端参数是否配置；实际商户扣款、退款仍未接通。

服务错误只存随机编号、功能类别、通用错误代码和时间，不保存请求正文、密钥、照片、原始错误文本或堆栈。最多200条，保留7天。错误记录供管理员查看，不作为完整监控、告警通知或自动重试系统。

## 操作记录

复用原有审计表，按北京时间近7/30/90天或全部、动作和关联编号搜索，每页25条。记录登录、文件收件/下载/删除/清理、订单处理、价格与报价、核验事件及备份动作。当前是单运营所有者模式，审计不能按不同员工区分操作人；用户提交等业务动作也可能生成记录。页面对关联编号和未知动作名进行HTML转义。

## 备份内容与一致性

“生成备份下载包”使用Node.js内置SQLite在线备份创建一致性快照，不直接复制正在运行的SQLite主文件，也不覆盖原数据库。快照移除登录会话和临时备份记录，并执行压缩整理、完整性检查。管理员密码和平台密钥来自进程配置，不写入备份。

默认仅包含数据库、清单与恢复说明。显式选择包含PDF时，仅复制快照中尚未过期、未删除的收件文件，并逐份检查字节数和SHA-256。源文件已丢失时清单标记缺失并报告数量，不声称完整；内容校验值不一致则整个备份失败。ZIP复用项目现有JSZip，以流写入私有磁盘，不新增服务端依赖。

数据库包含账号标识、订单联系人、价格、资金流水、操作记录等个人和运营资料。下载副本不受服务器自动删除控制，应按原始保存期限妥善保存或清理。仅数据备份不包含PDF原文件，恢复后需另外保留匹配的文件目录。

电脑和手机后台共用SQLite中的制作状态，同一时刻只制作一份备份。制作前预估磁盘余量；最多保留3份可下载临时包。备份位于私有数据目录的`backups`子目录，不在静态发布白名单。临时包最多保留10分钟，如原PDF或订单联系信息更早到期，则提前失效；主动删除原PDF时使现存临时备份全部失效。用户可提前删除临时包。

生成失败会关闭文件句柄并清理中间目录和部分ZIP；异常中断遗留工作文件会在制作租期结束后由清理任务回收。清理在服务启动、每分钟和页面检查时执行，停机后重启补清理。下载要求管理员会话，生成和删除另校验CSRF。

页面通过`X-Backup-Transfer: fetch`请求完整ZIP字节，服务端保持`application/zip`类型和文件长度，不向这类页面内传输强加附件响应头；普通访问保留附件下载响应。两种传输均要求相同的管理员会话，返回相同ZIP字节，并沿用到期、审计及私有访问限制。

浏览器保存前检查响应状态、文件类型和实际长度，空响应或下载不完整时明确提示失败。只有收到完整文件后才通过Blob交给浏览器保存；“已交给浏览器”不等同于用户已成功写入手机文件系统。不同浏览器的移动端保存能力需要实际设备验收。

## 恢复边界

每份有效临时备份可点击“校验可恢复性”。服务将其展开到私有临时目录，校验ZIP条目CRC、数据库及PDF的SHA-256、数据库完整性/关联关系、会话移除和清单对应关系，再在隔离副本中启动业务数据服务并执行原保存期限清理。结果显示可读用户、订单和资金事件数量、PDF校验/缺失/未包含数量及到期清理数量；这不会切换当前数据库或覆盖当前业务资料，完成后临时目录立即移除。仅数据备份和源PDF已丢失的备份会明确提示文件恢复边界，不能因数据库可读就声称包含完整PDF。

校验与备份制作在电脑/手机入口之间互斥。服务器不提供任意ZIP上传解压入口；只校验已登录管理员可访问、仍在有效期内的私有临时包。为限制本机内存及磁盘占用，校验下载包上限512MiB，数据库单条目256MiB、PDF单条目100MiB、展开总量2304MiB、条目数10000。使用项目固定版本JSZip的中央目录大小在解压前判断限制；拒绝未知条目、重复清单、不安全路径、内容校验不符及异常数据库。超过校验上限不影响原包下载，不代表备份内容损坏。

不提供在线覆盖数据库的恢复按钮。维护人员须先保存当前数据，停止所有电脑/手机后台入口，验证快照完整性及清单校验值，然后在私有目录恢复数据库及匹配PDF。恢复后按原始文件和联系信息到期时间立即清理，不能因恢复延长保存。登录会话已移除，需重新登录。该说明是离线恢复流程，不代表已执行正式生产恢复。

## 接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/admin/system` | 当前运行、空间、提醒、错误及最近10次备份记录 |
| `GET /api/admin/audit?days=30&q=&action=&page=1` | 操作记录，日期按北京时间 |
| `POST /api/admin/backups` | `{includeFiles:false}`或true；等待生成并返回备份编号、大小、到期及缺失PDF数量 |
| `GET /api/admin/backups/:id/file` | 已登录管理员下载有效ZIP，失效返回410 |
| `POST /api/admin/backups/:id/verify` | JSON对象请求，要求CSRF；隔离恢复并返回校验报告，损坏/不支持的备份返回422，失效返回410 |
| `DELETE /api/admin/backups/:id` | 删除非制作中的临时包；要求CSRF |

`node --test tests/system-admin.test.cjs`覆盖鉴权/CSRF、诊断、审计过滤、快照完整性、会话移除、PDF原字节与校验、缺失/损坏文件、到期与删除、两个服务入口的互斥，以及页面内ZIP传输与附件响应的字节一致性和访问控制。`node tests/system-admin.browser.cjs`要求浏览器实际产生成功的下载事件，读取保存文件并与鉴权接口原字节比对、执行ZIP校验；还验证模拟空响应的错误提示、删除及操作记录筛选和转义、桌面/手机尺寸。`TEST_LAN=1`使用局域网HTTP源，浏览器保存失败不能算此项验收通过。

恢复校验测试还涵盖在原库继续新增用户和修改联系人后读取旧快照、原库会话与PDF保持可用、损坏ZIP/数据库、CRC不符、路径穿越、伪造展开大小、原到期时间清理及跨入口互斥。浏览器验证“校验可恢复性”按钮、仅数据及含PDF结果、损坏包失败提示和手机尺寸布局。隔离恢复测试不等于已进行正式数据切换或物理灾备演练。
