# 打印订单与交付管理

## 流程

用户端入口为“小主角的纸质绘本打印服务”，按第1–10级选择并先展示故事与分册清单。完整每级计划30个故事，每10个故事装订一册，共3册；当前仅第1级6个已完成插画故事开放为1册样册，第2–10级筹备中。填写打印套数、配送和联系人并同意用途后，才生成文件并发送后台。每套当前为1册，故事数不乘入印本册数。历史单书提交接口继续兼容。

当前合集导出接口为 `downloadPrintFiles('level',{collectOnly:true})`，返回一个 `{bytes,bookId:'level-1',title:'第1级阅读故事集（现有6个故事样册）'}`。后台保存并下载原字节，不重排、拆页或生成附加页。A5排版与实际素材分辨率由导出模块负责；接收到文件不代表已经达到300ppi或完成印厂打样。

`preview/backend-functions.js` 的 `collectOrderDetails('level')` 调用同闭包的 `printServicePlan()`，只读取 `level/available/storyCount/volumeCount`；独立旧入口没有该函数时按现有6故事样册回退。新按钮调用 `submitPrint('level')`，重试调用 `submitPrint('level',true)`；不需要改上传或后台下载接口。订单请求附带 `printPlan:{level:1,storyCount:6,volumeCount:1}`。服务端仅接受当前样册与对应 `level-1` 文件，将规范化分册清单保存为不可变快照，并向用户和管理员详情返回 `printPlan`；旧订单为null，不补造故事数。管理员调整打印份数不会改写原内容清单。现阶段未来级别及30故事3册提交会被拒绝，内容准备完成后须扩充服务端清单和导出合同。

静态公网试用站没有收件服务；不能仅设置前端enabled为true。`operationsEnabled` 为false时禁止提交且不会打开确认表单或生成文件。正式收件应让同一个HTTPS源同时提供阅读端、`/api/` 与 `/admin`，反向代理到运营服务并使用私有持久磁盘。当前没有跨域收件或公开后台地址，不能把本机127.0.0.1或局域网192.168地址填作公网API。上线配置见[运营后台部署](README.md#部署配置)。

PDF全部接收后才创建订单。PDF收件编号与订单号分开：收件编号代表一份文件，订单号代表一次打印需求。文件或订单回执网络失败时，保留页面可重试；沿用各文件及订单的原始请求编号，不重复收件或建单。中途退出、刷新或更换资料会丢弃当前浏览器内尚未提交的联系信息和文件引用。已收到但尚未成单的PDF仍在原收件箱，不假称为完整订单。

“我的打印订单”显示当前设备的订单，可查看状态和快递单号；待确认、待付款阶段可填写原因取消。浏览器身份不能跨设备自动恢复，正式平台账号应通过平台SDK访问本人订单。

## 后台处理

后台新增“打印订单”，支持按北京时间近7/30/90天或全部时间、处理状态及关键词筛选。关键词匹配订单号、用户编号、联系人、电话、快递单号和绘本标题；列表每页25单。列表电话做遮罩，详情及主动导出CSV才包含完整联系信息。

订单详情提供绘本清单、每种印本份数、原PDF下载、联系人、配送方式、用户备注、内部备注、状态与发货、处理时间线。制作开始前可调整联系人和份数，但不能替换订单文件；制作后如出现问题应先记录异常。所有变更使用版本号，旧页面不能覆盖较新的后台操作。

状态如下：

- 待确认 → 待付款或待制作，可取消或记录异常。
- 待付款 → 待制作，可取消或记录异常。
- 待制作 → 制作中，可取消或记录异常；开始制作前要求PDF仍可下载。
- 快递订单制作中 → 已发货 → 已完成，发货必须填写快递公司及单号。
- 自取订单制作中 → 已完成，不创建快递发货状态。
- 异常需要处理说明，可恢复进入异常前的阶段或取消。
- 已完成、已取消结束流程。取消和异常必须说明原因。

这些是运营处理状态，不自行制造收入。新增[商品报价与支付关联](billing.md)：启用商品价格后可报价，关联付款必须服务端核验才能推进制作；退款登记不执行真实退款。未报价的旧人工订单保留手工处理方式。已付订单不能直接修改联系人/份数，报价后修改资料会使报价失效。登记快递单号不会调用物流公司或向印厂发送文件。

后台CSV导出沿用当前日期、状态和搜索筛选，最多10000单，超出时要求缩小范围。文件包含订单、联系人和地址，保存在管理员自行下载的位置，不纳入静态站点发布。输出UTF-8并转义CSV字段及公式前缀，避免联系人或备注被当作表格公式执行。

## 保存期限与访问

PDF默认30天，继续由收件服务按期清理。订单联系信息默认自创建起90天，服务器通过 `ORDER_CONTACT_RETENTION_DAYS` 可设置为1–365天；页面提示与服务端配置一致。到期清除联系人、电话、地址、用户与内部备注、快递公司、快递单号，并清除处理说明中可能含有的个人信息。未完成订单转异常且只允许取消；已完成、已取消保留其终态，不把到期当作已交付。

订单编号、用户编号、绘本编号与份数、操作时间及状态保留用于运营对账。数据库、PDF和测试输出均留在私有持久目录；备份也应执行相同的个人信息保留策略。

用户端仅能访问自己的订单，不能指定他人用户编号或篡改运营字段；用户看不到内部备注及管理员处理说明。后台查询、导出、文件下载需要管理员登录；修改另外要求CSRF凭证。审计日志只记录动作及订单编号，不记录电话、地址或完整请求体。

旧版打印收件和下载接口继续保留，已有文件不自动捏造联系人、份数或发货信息迁为新订单。后台原“打印收件箱”继续处理历史文件，新的“打印订单”负责订单交付状态。

## 接口

| 接口 | 用途 |
| --- | --- |
| `POST /api/print-orders` | 本人使用已接收的PDF创建订单 |
| `GET /api/print-orders` | 分页列出本人订单 |
| `GET /api/print-orders/:id` | 本人查看状态、联系信息和发货信息 |
| `POST /api/print-orders/:id/cancel` | 本人在待确认或待付款阶段说明原因取消 |
| `GET /api/admin/print-orders` | 后台筛选、搜索和分页 |
| `GET /api/admin/print-orders/:id` | 后台完整详情 |
| `PATCH /api/admin/print-orders/:id` | 带version修改信息、份数或状态 |
| `GET /api/admin/print-orders/export` | 导出筛选结果CSV |

创建请求：

```json
{"requestKey":"原请求编号至少16位","items":[{"receiptId":"本人上传得到的文件UUID","copies":2}],"recipient":{"method":"shipping","name":"联系人","phone":"13800000000","address":"完整收货地址"},"note":"需要确认的事项","consentVersion":"print-order-v1","printPlan":{"level":1,"storyCount":6,"volumeCount":1}}
```

`printPlan`为当前打印服务附带的有限字段，旧单书调用可以省略。服务端返回的清单包含 `sample:true` 和 `volumes:[{number:1,firstStory:1,lastStory:6,storyCount:6,bookId:"level-1"}]`；清单仅核对当前目录与文件标识，不自动分析PDF内容或认证印刷质量。

`method`可选 `shipping`、`pickup`；自取不需要地址。每单1–40份文件，同一文件不得重复出现，每本1–100册。相同请求编号内容不一致时返回409，过期文件返回410。

原生两端SDK新增 `createPrintOrder({...input,consent:true})` 与 `getPrintOrder(id)`，先通过已有 `submitPdf` 获取文件编号再成单。手机页面须展示与服务器一致的联系信息用途及保留期限，不能仅因登录或保存头像自动下单。账号切换后旧响应不会显示到新账号。

## 验证

`node --test tests/print-orders.test.cjs tests/platform-sdk.test.cjs tests/admin.test.cjs tests/operations-service.test.cjs` 验证身份隔离、联系人与份数、去重、状态机、版本冲突、发货条件、CSV及到期清理。`node tests/print-orders.browser.cjs` 验证实际PDF生成到订单提交，模拟订单回执丢失与合集回执丢失后的重试、后台修改/发货/下载/导出、用户查看与取消，以及桌面和手机布局。平台原生登录使用模拟，不代替微信、抖音真机或真实物流/支付验收。
