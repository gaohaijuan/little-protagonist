# 小小主角运营后台

2026-10-27更新：完整浏览器试用现采用第一级15篇、1册合集。当前目录、正文、识字统计、PDF与订单通过 `miniprogram/lib/current-edition.js` 统一；商品编号 `level-1-fifteen-v1`，价格初始为空。旧6篇订单保留原有快照与重试兼容，不能混用旧文件或价格。下文6篇样册、30篇计划为历史说明。详情见 [浏览器试用说明](../docs/browser-trial.md)。

## 本机运行

需要 Node.js 24，使用内置 SQLite，无需安装服务端依赖。项目根目录运行 `npm run admin`，或双击“打开管理后台.cmd”。

- 后台：`http://127.0.0.1:4180/admin`，本机默认密码为 `111`，重启后保持不变，数据保留。本机简易密码仅在未配置公开源且绑定本机地址时使用。
- 配套阅读端：`http://127.0.0.1:4180/`。此地址的“小主角的纸质绘本打印服务”会展示实际内容清单，填写配送资料并确认用途后才生成和提交文件。
- `npm run preview` 的4173端口及现有静态试用站不连接后台；打印确认按钮禁用并准确提示服务未连接；制作校样工具由集成方单独保留。

打印服务当前开放第1级6故事、1册样册，其他等级筹备中。完整每级30故事、每10故事1册的规则仅为后续内容规划；旧单书接口继续兼容。当前样册共用封面，只生成并发送一个PDF，打印份数应用于整册；后台印本种类记为1，故事数不乘入册数。文件或订单回执丢失时，保留页面可用原请求编号重试，不重复收件或建单。离开页面会取消剩余任务，刷新后未发送文件不保留。阅读不依赖统计接口，保存头像不生成打印文件。

### 手机在同一局域网测试

运行 `node server/start-mobile.cjs`，使用本机唯一的私有IPv4地址监听4181端口，控制台显示手机阅读和后台链接。手机须连接同一局域网，电脑和服务保持运行；地址变化后重启服务并使用新链接。多块局域网网卡时用 `MOBILE_TEST_IP` 明确选择本机地址，`MOBILE_TEST_PORT` 可修改端口。不会绑定0.0.0.0或公网地址，不更改Windows防火墙和路由器设置。

手机后台按用户要求固定使用密码 `111`，重启后保持一致，并将旧测试密码更新为111；电脑4180端口的本机密码同样为111。此简易密码只允许在显式手机测试模式、本机私有IPv4地址及同一网段访问时使用；公开部署仍要求至少12位密码。两入口复用同一私有数据库和文件目录，但管理员会话各自独立。局域网入口使用HTTP，只供可信的同网测试，不作为公网部署方案；手机拍照等需要HTTPS的浏览器能力应另用HTTPS环境验证。

阅读端统计/打印重试编号和后台退款申请编号使用浏览器`crypto.getRandomValues`生成128位随机值，不依赖仅安全上下文提供的`crypto.randomUUID`，以兼容局域网HTTP访问。`node tests/collection-orders.browser.cjs`在真实局域网HTTP源测试收件、重试与下载；`TEST_LAN=1`时可运行`tests/print-orders.browser.cjs`、`tests/billing.browser.cjs`验证真实PDF和后台操作。测试使用桌面Chrome及手机尺寸窗口，不替代手机真机验收。

商品价格、报价、支付准备单关联、退款申请及用户详情见[报价与支付关联](billing.md)。价格初始为空，需运营方自行填写；微信/抖音实际扣款与渠道退款尚未开通。

“运行与备份”检查文件空间、缺失PDF、超时订单及异常收款；“操作记录”支持动作和关联编号查询。可生成私有数据库快照并选择包含有效PDF，临时ZIP最多保留10分钟；“校验可恢复性”在独立临时目录读回数据库与PDF，检查内容及原保存期限清理，不覆盖当前业务数据。下载副本须按原期限自行保存或清理。内容、权限、接口及离线恢复边界见[运行检查与备份](system-admin.md)。

## 数据、权限与口径

打印交付新增独立订单模块，见[打印订单与交付管理](print-orders.md)，支持联系人、份数、配送、状态、发货及CSV导出；旧PDF收件仍可使用。

管理员登录有效8小时，文件下载、列表、状态变更、删除均需授权；管理写操作另校验CSRF凭证。单管理员角色仅供运营所有者使用。SQLite、个性化PDF、测试截图留在 `.local/`，不进入静态发布白名单。数据库和文件目录都应位于私有持久磁盘，不能配置为Web静态目录。后台记录登录、接收、下载、状态变更及文件清理审计。

PDF默认保存30天，启动时及每分钟清理到期文件；停机期间不执行清理，重启即补清理。可立即删除文件，收件元数据保留用于客服查询，个性化书名同时清除为绘本编号。异常中断遗留且超过5分钟的无收件记录文件会清理。默认单份最多100 MiB、总文件2 GiB，超限拒收；文件接收串行写磁盘，校验PDF头尾并提供附件下载。头尾校验不是完整的PDF安全扫描，运营电脑应使用受维护的PDF阅读器。

页面支持北京时间近7/30/90天和全部时间筛选，列表每页25条。累计用户为全部用户；新增用户和用户列表按加入时间；活跃按访问、开始阅读、分享事件去重；打印申请按PDF收件数，不代表付款、份数或印厂订单。浏览器为设备标识，清站点数据或换设备可能重复计数；不会回收历史本地资料填充统计。微信端沿用已验证的家长账号编号。

邀请来源只在新用户建立时绑定，旧用户和自己不能重新绑定。分享计数表示分享发起；浏览器分享返回不代表接收方成功打开。邀请转化为所选加入期的新用户截至当前有已核验付款，退款不撤销“曾经付款”标记。不发奖励，不构成防刷或佣金结算系统。

收入以整数分存储，按收到核验事件的时间统计实付、退款和净额；净额不扣手续费。收款渠道未开通时显示未配置和空数据。

## 部署配置

环境变量仅在服务端设置：

| 变量 | 含义 |
| --- | --- |
| `ADMIN_PASSWORD` | 可覆盖本机默认密码 `111`；公开部署至少12位，未设置时使用随机密码 |
| `ADMIN_PORT` / `ADMIN_HOST` | 默认4180 / 127.0.0.1 |
| `PUBLIC_ORIGIN` | 公开访问的HTTPS源，如 `https://reader.example.com`，用于检查请求来源 |
| `ADMIN_DATA_DIR` | 私有持久数据目录，默认 `.local/admin-data` |
| `PRINT_RETENTION_DAYS` | 个性化PDF保存天数，1–365，默认30 |
| `ORDER_CONTACT_RETENTION_DAYS` | 订单联系人、地址及备注保存天数，自提交起计算，默认90 |
| `ACCOUNT_BRIDGE_SECRET` | 与微信账号云函数共用的服务端签名密钥，建议32字节随机值 |
| `PAYMENT_EVENT_SECRET` | 商户核验服务推送付款事件的独立签名密钥，建议32字节随机值 |
| `WX_APP_ID` / `WX_APP_SECRET` | 可选的自建微信登录入口；已有账号云函数应优先使用账号桥接 |
| `DOUYIN_APP_ID` / `DOUYIN_APP_SECRET` | 抖音小程序原生登录的服务端凭证 |

公开部署需HTTPS反向代理到本进程、持久磁盘、备份策略和防火墙；直接绑定非本机地址时启动器要求配置HTTPS源与固定密码。反向代理上传限制至少100 MiB，读取超时至少120秒；不要代理私有磁盘为静态文件。备份应按SQLite一致性备份方式处理数据库，并与PDF文件对应保存；备份中个性化文件的期限应同样落实。此交付未部署公网，不是微信发布结果。

## 微信账号衔接

微信与抖音新增统一的原生SDK适配，见[平台SDK接口与原生接线](platform-sdk.md)。保留以下微信云开发方式，两者使用同一微信账号编号；抖音来源单独标识。

复用 `cloudfunctions/account` 中的账号验证，新增 `operations-session` 操作。先通过 `account.requireUser` 验证现有云会话与微信可信上下文，再由云函数签名调用运营后台 `/internal/account-session`。前端不能提供任意账号编号，不接收原始照片、昵称或手机号。

1. 先完成原有账号云函数及真实小程序AppID配置。
2. 云函数环境变量设置 `OPERATIONS_ORIGIN` 为运营服务HTTPS源，`ACCOUNT_BRIDGE_SECRET` 与服务器一致；重新部署完整account云函数目录，包含 `operations-bridge.js`。
3. `miniprogram/config/operations.js` 设置 `baseUrl` 为同一HTTPS源，并在微信后台配置request合法域名。
4. 登录后访问、开始阅读及分享可记录；未配置或失败不阻塞阅读。微信分享沿用首页 `onShareAppMessage`，首次登录后准备邀请码。运营会话最长7天，账号切换或退出时尝试撤销，网络失败则在到期后失效。

`miniprogram/services/operations-service.js` 提供 `submitPdf({filePath,bookId,title,requestKey,consent})`，读取已生成本地PDF并发送；重试须复用同一个请求编号。**当前微信原生阅读页尚无PDF生成和提交按钮；完整打印提交流程已接入浏览器版。不能把这个接口描述为微信真机打印已完成。** 正式原生接入还需复用合格的原生PDF生成流程，并在提交前展示与服务器一致的用途、保存期限和家长确认。

## 付款核验事件接口

`POST /internal/payments` 不是微信支付通知地址，不直接接收前端“支付成功”。商户服务应先按支付渠道要求完成通知验签、查询订单、核对金额和币种，再提交以下归一化事件：

```json
{"eventId":"event_unique_01","orderId":"merchant_order_01","transactionId":"provider_transaction_01","userId":"已存在的后台用户编号","kind":"paid","amountFen":1990}
```

退款使用 `kind: "refund"`，新的事件编号和退款流水号，对应原订单及同一用户。支持部分退款，累计不得超过实付。相同事件及相同内容重复接收不重复入账；事件编号被用于不同内容、订单重复付款、流水重复会返回409。`eventId`、`orderId`、`transactionId`限1–100位字母、数字、下划线、短横线。

请求头 `X-Payment-Timestamp` 为当前毫秒时间戳，允许误差5分钟；`X-Payment-Signature` 为 `HMAC-SHA256(PAYMENT_EVENT_SECRET, timestamp + "." + 原始JSON请求体)` 的十六进制值。签名密钥禁止放在小程序或浏览器。账号桥接使用相同签名构造，但头为 `X-Account-Timestamp` / `X-Account-Signature`，密钥独立。

已提供商品定价、报价及本地付款准备单，关联事件额外要求currency和channel与付款单匹配，详见[billing.md](billing.md)。尚未实现商户渠道下单、微信/抖音支付通知验签与主动查询、实际退款、物流查询或佣金发放；这些需要正式账号、商户号及产品规则。

## 验证

`npm run test:admin` 验证收件下载、鉴权、CSRF、重试去重、到期清理、邀请归因、付款签名及退款记账。`npm run test:admin-browser` 使用本机Playwright/Chrome和pdf-lib依赖运行真实生成、上传失败重试、后台下载、状态修改与手机布局验证；依赖路径与现有浏览器测试保持一致。微信云环境、真实支付和真机性能另行验收。

实现依据：[Node.js SQLite](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)。
